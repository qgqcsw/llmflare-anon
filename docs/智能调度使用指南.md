# 智能调度使用指南

本文说明 LLMflare-Anon 的「智能调度」能力：免费模型筛选、路由组与故障转移、额度调度、健康度熔断、模型测试。

> 对应版本：`v1.4.0-anon.0` 起提供。全部功能都在后台「智能调度」页签下，复用你已有的管理员账号会话，**没有新增任何登录方式或 Cloudflare 资源**。

## 1. 它解决什么问题

各家免费 API 的额度和稳定性都不一样：有的每天只有几百次，有的会突然 429，有的把免费模型藏在模型名后缀里。手动轮换 Key 和地址很麻烦，一旦某个上游挂了，调用就直接失败。

智能调度把这件事收敛成三句话：

1. **哪些是免费的**——自动识别并打标，免费模型直接进白名单。
2. **该用哪一个**——按你选的模式挑通道，撞上限流自动换下一个。
3. **还能不能用**——失败的通道暂时拉黑，恢复后自动放回来。

**关键承诺：不建路由组时，网关行为与升级前完全一致。** 老用户什么都不用改，也不会因为升级而多出任何限制。

## 2. 免费模型筛选与标记

### 2.1 判定依据与优先级

判定按证据强度从高到低进行，先命中的规则决定结论：

| 优先级 | 规则 | 说明 |
| --- | --- | --- |
| 1 | 上游确认 | 上游模型目录明确标注零价格（如 OpenRouter 的 `pricing.prompt = 0`） |
| 2 | 实测探测 | 实际发起一次最小请求成功，且上游回执表明免费 |
| 3 | 用户白名单 | 你在提供商配置里手动声明该模型免费 |
| 4 | 命名推断 | 命中官方免费档命名规则，见下表 |
| — | 未命中 | 判为付费 |

### 2.2 命名推断规则

| Provider | 规则 | 举例 |
| --- | --- | --- |
| OpenRouter | 模型 ID 以 `:free` 结尾 | `meta-llama/llama-3.1-8b-instruct:free` |
| 智谱 BigModel | `flash` 系列 | `glm-4-flash`、`glm-4-flashx` |
| Google AI Studio | `gemini-*-flash` | `gemini-2.0-flash` |
| Groq | `instant` 系列 | `llama-3.1-8b-instant` |
| SiliconFlow | `free` 结尾 | `Qwen2.5-7B-Instruct-free` |

排除规则优先于纳入规则：带 `-exp`、`-experimental`、`-preview`、`-thinking`、`-pro`、`-ultra` 的模型不会被判为免费，避免把试用档当成长期免费。

### 2.3 四个徽标等级

| 徽标 | 含义 | 可信度 |
| --- | --- | --- |
| **免费** | 上游目录或实测证实零价格 | 高，可放心依赖 |
| **免费·白名单** | 你手动声明为免费 | 取决于你的声明 |
| **免费·推断** | 按命名规则推断 | 中，建议观察用量 |
| **付费** | 未命中任何免费规则 | — |

### 2.4 操作方式

在「智能调度 → 免费模型」：

- **重新筛选全部**：遍历所有启用的提供商，拉取模型目录并重新判定。免费模型会**自动并入该提供商的启用白名单**，随后立即出现在 `/v1/models`，客户端可直接选用。
- **刷新该提供商**：只刷新单个提供商，适合新增 Key 后单独更新。

每次判定都会返回命中的规则列表，面板上直接显示原因（例如「上游目录标注零价格」），便于你判断可信度。

## 3. 路由组与故障转移

### 3.1 概念

一个**路由组**就是一组「提供商 + 模型」成员，加一条调度策略。客户端请求时指定组名，网关在组内按策略挑一个通道发起；失败则换下一个。

### 3.2 如何调用

建好组之后，组会以虚拟模型的形式出现在 `/v1/models` 列表里：

```
group/<组ID>
```

客户端直接用它当模型名：

```json
{
  "model": "group/main",
  "messages": [{ "role": "user", "content": "你好" }],
  "stream": true
}
```

也可以直接用中文组名（`model: "group/主线路"`），两者等价。Claude Code、Codex 等客户端可以在模型下拉里直接选到 `group/xxx`，无需手动输地址。

### 3.3 七种调度模式

| 模式 | 排序依据 | 适用场景 |
| --- | --- | --- |
| `smart` | 免费优先 → 额度余量最多 → 手动权重 → 组内顺序 | 默认，日常通吃 |
| `order` | 严格按成员顺序 | 明确的主备关系 |
| `rotate` | 按游标轮转起点 | 把流量摊平到多个免费额度 |
| `usage` | 本月已用 Token 最少者优先 | 避免某个 Key 提前打空 |
| `pace` | 额度使用比例最低者优先 | 多方额度大小不一时更公平 |
| `free-first` | 免费模型一律排前 | 严格控制成本 |
| `cheapest` | 免费 → 匿名上游 → Workers AI → 自带 Key | 只看钱 |

### 3.4 故障转移的判定规则

失败不是一律重试——重试无效的错误会白烧额度：

| 上游返回 | 处理 | 理由 |
| --- | --- | --- |
| `429` 限流 / 额度耗尽 | 切换到下一个成员 | 换通道确实能解决 |
| `408` / `504` / `524` 超时 | 切换并重试 | 多为上游瞬时拥塞 |
| `5xx` 服务端错误 | 切换并重试 | 上游自身故障 |
| 网络错误 / 连接中断 | 切换并重试 | 链路问题 |
| `401` / `403` 鉴权失败 | 切换，但**不重试同一成员** | Key 失效，重试无意义 |
| `400` 参数错误 | **直接返回给客户端** | 换谁都一样错，重试纯浪费 |

### 3.5 可调参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 最多尝试成员数 | 3 | 一次请求最多换几个通道，1–10 |
| 首字节超时 | 30000 ms | 超过即判定该通道不可用并切换 |
| 只走免费 | 关 | 开启后组内付费通道直接被过滤 |

### 3.6 默认组

若配置了**默认组**，客户端**不指定模型**（或模型为空）时自动走该组。不配置则维持原有行为：使用提供商的默认模型。

## 4. 额度调度

### 4.1 三层窗口

给每个提供商单独设置上限，任意一层用尽即跳过该通道：

| 字段 | 说明 | 重置周期 |
| --- | --- | --- |
| 每分钟请求数 | 应对上游 RPM 限制 | 滑动分钟 |
| 每日请求数 | 应对上游 RPD 限制 | 每日零点（UTC） |
| 本月 Token | 应对免费额度按量计费 | 每月一号 |
| 本月请求数 | 应对按月计次的配额 | 每月一号 |

**未填写即视为不限制**，不会因为升级而给现有提供商加限制。

### 4.2 并发安全的预留机制

额度不是「请求发完再记账」，而是三步：

1. **预留**：请求前先占住额度（请求数 +1，按预估 token 占位）。
2. **执行**：真正打上游。
3. **结算**：成功则用真实 token 数校正；失败则整笔回滚。

这样并发 10 个请求也不会把「每天 100 次」打成 120 次。额度已满时，调度会**直接跳过**该通道，不会硬发请求去撞 429。

### 4.3 面板显示

额度页签用进度条展示每个提供商的四层用量，70% 变黄、90% 变红。已耗尽的通道会显示剩余重置时间。

## 5. 健康度与熔断

### 5.1 工作机制

连续失败达到阈值后，该通道进入**熔断**状态（暂时不再被调度）。冷却时间按失败次数指数增长：

| 连续失败 | 冷却时间 |
| --- | --- |
| 1 次 | 15 秒 |
| 2 次 | 30 秒 |
| 3 次 | 60 秒 |
| … | … |
| 上限 | 10 分钟 |

冷却结束后进入**半开**状态：放行一次真实请求探测，成功则完全恢复，失败则继续熔断。

### 5.2 双层记录

熔断记录同时写在两个层级：

- **提供商级**：某个 Key 整体 429 或套餐耗尽时，该提供商下所有模型一起拉黑。
- **提供商 + 模型级**：单个模型不可用时，只拉黑这一个，同提供商的其他模型仍可用。

调度时两层取更严格的一方。这样既不会因为一个模型坏了浪费整家提供商，也不会在整家都挂掉时让每个模型各撞一次墙。

### 5.3 面板操作

「健康度」页签展示每个通道的熔断状态、连续失败数、最近状态码、恢复倒计时，支持：

- **单个重置**：立刻解除某个通道的熔断。
- **全部重置**：清空所有记录，适合换 Key 或换网络后重新开始。

## 6. 模型一键测试

### 6.1 单模型测试

选提供商和模型，发一次最小请求，返回：

- 是否可用
- 首字延迟（ms）
- 回复摘要（截断展示）

### 6.2 批量测试

一键跑完所有已启用模型，并发 4，给出：

- 总数 / 成功数 / 失败数
- 其中免费模型可用数量
- 逐项结果表（提供商、模型、结果、延迟）

### 6.3 注意事项

- 测试会**真实消耗上游额度**，批量测试请控制频率。
- 测试结果**不写入用量统计**，不会影响你的月度报表。
- 测试**不改变熔断状态**，纯粹是旁路探测，不会污染调度决策。

## 7. 数据存放与兼容性

| 项目 | 存放位置 | 说明 |
| --- | --- | --- |
| 路由组与默认组 | 既有 KV 命名空间 `CONFIG` | 复用，不新增命名空间 |
| 额度计数 | 既有 KV 命名空间 `CONFIG` | 复用，不新增命名空间 |
| 熔断状态 | 内存（按 Env 实例隔离） | 不进存储，实例回收后自动清零 |
| 免费标记 | 提供商配置字段 | 与既有字段同层 |

**兼容性保证**：

- 历史数据没有任何新字段时，一律按「不限制 / 未熔断 / 按原逻辑」处理，**无需数据迁移**。
- 没有创建路由组时，`runRouted` 直接返回空，网关走原来的单提供商路径，**行为与升级前完全一致**。

## 8. 常见问题

### 免费模型会不会其实收费？

「免费·推断」等级只是命名匹配，官方可能随时调整。建议对这类模型观察一两天用量；「免费」（上游证实）等级才适合长期依赖。

### 路由组会不会拖慢速度？

只在**请求进入时**多一次策略计算（纯内存排序，微秒级），上游请求与响应流式转发完全不变。组内第一个通道可用时，延迟与直连相同。

### 熔断状态为什么重启就没了？

熔断是**瞬时状态**，刻意放在内存里：Worker 实例回收后自动清空，避免陈旧状态误伤正常通道。需要持久化时可在 `health.ts` 改为写入 KV（会略微增加每次请求的开销）。

### 额度用尽了怎么办？

调度会自动跳过该通道，面板显示剩余重置时间。想立刻恢复可以手动清空该提供商的额度限制。

### 一个组里有多个免费模型，会都用上吗？

会。`rotate` 模式把流量摊到各成员，`usage`/`pace` 模式优先用余量最多的那个。若只想用某一个，用 `order` 模式并把它排在第一位。

### 客户端看不到 `group/xxx` 模型？

确认组已保存且处于启用状态（成员数 > 0）。`/v1/models` 只列出启用的组。部分客户端有模型缓存，需要重启或手动刷新模型列表。
